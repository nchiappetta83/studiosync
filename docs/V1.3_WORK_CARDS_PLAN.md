# StudioSync V1.3 — Shared Work Cards

## Product decision

V1's existing `tasks` records remain the scheduled project assignments used in
Dashboard. They retain the existing priority, due date, short scheduling
summary, staff assignment, rollover, Excel, and shared-drive behavior.

V1.3 adds a separate, shared work-card layer for the small number of actionable
items beneath a scheduled project. Work cards belong to a project and scheduling
week, not to one person's V1 assignment record, so every staff member assigned
to that project can see the same cards.

## Roles

- Partners and Senior Staff create, edit, assign, and complete work cards.
- Assigned staff can view every card for a project they are assigned to.
- A staff member's `Work on this` selection is personal; it never implies that
  another assignee is also working on the same card.
- Existing per-person V1 editing controls remain the source of any future staff
  editing exception.

## V1.3 data model

`work_cards` is keyed by project and `week_of`. It stores the title,
description, optional planned minutes, optional date window, completion state,
creation metadata, and order. `work_card_assignees` permits one or more named
staff assignees. `work_card_focus` stores one active work card per person and is
intentionally separate from the shared card state.

Existing V1 `sub_tasks` remain action items and are not repurposed.

## Rollout note

All computers that participate in the shared office must be updated to V1.3
before anyone creates the first work card. V1.2 safely ignores no data during
normal scheduling, but it cannot interpret the new `work-card-*` shared-drive
events. The existing Dashboard and MyTasks installers will therefore be
released together after the final Dashboard disclosure and visual checks.
